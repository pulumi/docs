{{- /* The "author(s) • date • N min read" byline used on cards. Avatars + name/count, a muted bullet, then the post date, then the reading time. Params: page (required) the post page dark true → white text on a violet-950 surface readingTime true → include the "N min read" segment (skipped outright on the tighter card variants, e.g. small) The byline never wraps, at any card width, without the caller having to know how wide its grid is: - The row is nowrap, and each bullet is grouped with the segment it introduces, so a separator can never be left stranded at a line end. - Reading time is the first thing to go. A container query drops it below 22rem, which is roughly where the full byline stops fitting on one line (a 32px avatar, a typical author name, a date, and "N min read"). The blog's own 3-column grid is comfortably above that and keeps it; a 4-column grid falls below and loses it. - Below that, the author name truncates. It's the only variable-width segment, so it's the one that should give — the date and reading time are fixed-width and stay whole. This is the only container-query use in the theme so far. Tailwind v4 ships them in core, so it needs no plugin; `@container` here makes the byline wrapper the query root, and the card's width is what the query sees. */ -}} {{- $page := .page -}} {{- $dark := .dark -}} {{- $fg := cond $dark "text-white" "text-service-black" -}} {{- $authors := $page.Params.authors -}}
{{- with $authors -}} {{ partial "blog/avatars.html" (dict "authors" . "dark" $dark) }} {{- end -}} {{- with $authors }}•{{ end -}} {{ $page.Date.Format "Jan 2, 2006" }} {{- if .readingTime -}} • {{ $page.ReadingTime }} min read {{- end -}}
