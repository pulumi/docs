Prefer this over hand-writing a `blog/cta-card` for an event: a CTA card has to restate the title, date, and blurb, and those copies go stale. Usage (one positional page path): {{< blog/card "/events/neo-in-a-docker-sandbox/" >}} {{< blog/card "/blog/pulumi-neo/" >}} The card is full width, never side by side: the text column is only so wide, and a full-width card reads as part of the post rather than as an ad unit. So one card per shortcode — several in a row is just several shortcodes. The path is the only parameter; everything the card shows comes from the target page. The exception is an event that runs more than once: that renders one stacked card per session still ahead, each linking to its own session tab, because the reader's question is which date works for them. It collapses back to a single card once every session has run. (This assumes `youtube_url` isn't set until then — a recording removes the session tabs, so an early one would leave these cards linking to anchors the event page no longer has. See the warning in archetypes/event/index.md.) Parameters (positional only): one absolute content path, resolving to a page under /events/ or /blog/.
